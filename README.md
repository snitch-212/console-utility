# depgraph

Инструмент визуализации графа зависимостей пакетов Ubuntu (apt).
Практическая работа № 2 по дисциплине «Конфигурационное управление»,
вариант 25.

Ограничение задания: менеджеры пакетов (`apt`, `dpkg` и т. п.) и сторонние
библиотеки для получения зависимостей не используются. Проект написан на
Python 3.9+ и использует только стандартную библиотеку.

## 1. Общее описание

Программа принимает параметры анализа из командной строки, скачивает индекс
пакетов репозитория Ubuntu (файл `Packages`), находит в нём заданную версию
пакета и выводит его прямые зависимости.

Статус реализации по этапам:

| Этап | Содержание                             | Статус        |
|------|----------------------------------------|---------------|
| 1    | Прототип CLI с настраиваемыми опциями  | готово        |
| 2    | Сбор данных (прямые зависимости apt)   | готово        |
| 3    | Граф зависимостей, BFS, тестовый режим | не реализован |
| 4    | Обратные зависимости                   | не реализован |
| 5    | Визуализация (Graphviz)                | не реализован |

Вывод параметров в формате «ключ: значение» требовался только на этапе 1;
начиная с этапа 2 программа выводит прямые зависимости пакета.

## 2. Описание функций и настроек

### Параметры командной строки

| Опция                     | Описание                                          | По умолчанию |
|---------------------------|---------------------------------------------------|--------------|
| `-p`, `--package`         | имя анализируемого пакета                         | обязательна  |
| `-r`, `--repo`            | URL индекса `Packages` (remote) или путь к файлу тестового репозитория (test) | обязательна |
| `-m`, `--repo-mode`       | режим работы с репозиторием: `remote` или `test`  | `remote`     |
| `-V`, `--package-version` | версия пакета                                     | обязательна в `remote`, необязательна в `test` |
| `-d`, `--max-depth`       | максимальная глубина анализа зависимостей         | `1`          |

Глубина `--max-depth` проверяется уже сейчас, но используется начиная с
этапа 3 (транзитивные зависимости). Режим `test` на этапе 2 не поддержан:
программа сообщает об этом ошибкой, реализация будет на этапе 3.

### Что передавать в `--repo`

URL файла индекса `Packages` нужного компонента репозитория Ubuntu. Файл может
быть несжатым, `.gz` или `.xz` — формат определяется по содержимому.
Допустимые схемы: `http`, `https`, `file` (последняя нужна для работы без
сети). Пример адреса индекса:

```
http://archive.ubuntu.com/ubuntu/dists/jammy/main/binary-amd64/Packages.gz
```

Пакет должен находиться именно в этом индексе: пакеты из `universe`
ищутся в `.../universe/binary-amd64/Packages.gz`, обновления — в индексах
`jammy-updates` и `jammy-security`.

### Правила проверки параметров

- **package**: в режиме `remote` — имя пакета Debian (от 2 символов, строчные
  латинские буквы, цифры, знаки `+ - .`, первый символ — буква или цифра);
  в режиме `test` — только большие латинские буквы (`A`, `B`, …).
- **repo**: в режиме `remote` — URL со схемой `http`, `https` или `file`;
  в режиме `test` — путь к существующему читаемому файлу.
- **repo-mode**: `remote` или `test`.
- **package-version**: синтаксис версии Debian `[эпоха:]версия[-ревизия]`,
  например `5.1-6ubuntu1` или `1:2.5-1`; версия начинается с цифры.
  Сравнение с индексом точное: версия должна совпасть со значением поля
  `Version` символ в символ.
- **max-depth**: целое число не меньше 1.

### Какие зависимости считаются прямыми

Объединяются поля `Pre-Depends` и `Depends` выбранной версии пакета в том
порядке, в котором они записаны в индексе. Поля `Recommends`, `Suggests`,
`Conflicts` и т. п. не учитываются. Каждое требование выводится отдельной
строкой в синтаксисе Debian:

- `libc6 (>= 2.34)` — пакет с ограничением версии (операторы `<<`, `<=`, `=`,
  `>=`, `>>`);
- `python3:any` — с квалификатором архитектуры;
- `mail-transport-agent | postfix (>= 3.0) | exim4` — альтернативы: подойдёт
  любой из перечисленных пакетов.

### Обработка ошибок

Любая ошибка печатается в `stderr` в виде `Ошибка: <описание>`, программа
завершается с кодом `1`; при успехе код возврата `0`. Обрабатываются:

- некорректные параметры (включая неизвестную опцию и опцию без значения);
- недоступный индекс: нет сети, неизвестный хост, ответ сервера 404 и т. п.,
  отсутствующий файл при `file://`;
- повреждённый архив `.gz` / `.xz`;
- пакет отсутствует в индексе;
- версия отсутствует в индексе (в сообщении перечислены доступные версии);
- нераспознанная запись о зависимости.

### Структура проекта

```
src/depgraph/
    __main__.py   запуск: python3 -m depgraph
    cli.py        точка входа, вывод зависимостей, коды возврата
    config.py     разбор и проверка параметров (класс Config)
    apt.py        загрузка индекса Packages, разбор зависимостей
    errors.py     исключения приложения
tests/            модульные тесты (unittest)
tests/data/       небольшой учебный индекс Packages для тестов
Makefile          цели run и test
run.sh            скрипт запуска
```

Основные функции `apt.py`:

| Функция                    | Назначение                                          |
|----------------------------|-----------------------------------------------------|
| `download(url)`            | скачать содержимое по URL (http, https, file)       |
| `decompress(data, url)`    | распаковать gzip / xz по сигнатуре                  |
| `find_entries(text, name)` | найти все записи пакета с точным именем             |
| `select_version(...)`      | выбрать запись нужной версии                        |
| `parse_dependencies(text)` | разобрать поле Depends в список `Dependency`        |
| `get_direct_dependencies(url, name, version)` | полный цикл: от URL до списка зависимостей |

## 3. Сборка и запуск тестов

Сборка не требуется, нужен только Python 3.9 или новее.

Запуск тестов:

```
make test
```

или без make:

```
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Запуск программы:

```
./run.sh --help
make run ARGS="--help"
```

## 4. Примеры использования

Реальный репозиторий Ubuntu (нужен доступ в интернет). Если указанной версии
нет в индексе, программа перечислит доступные:

```
./run.sh -p bash -V 5.1-6ubuntu1 \
    -r http://archive.ubuntu.com/ubuntu/dists/jammy/main/binary-amd64/Packages.gz
```

Работа без сети с учебным индексом из `tests/data` (адрес вида `file://`):

```
$ ./run.sh -p bash -V 5.1-6ubuntu1 -r file://$PWD/tests/data/Packages
Прямые зависимости bash 5.1-6ubuntu1 (4):
  libc6 (>= 2.34)
  libtinfo6 (>= 6)
  base-files (>= 2.1.0)
  debianutils (>= 2.15)

$ ./run.sh -p demo-editor -V 1.2-1 -r file://$PWD/tests/data/Packages
Прямые зависимости demo-editor 1.2-1 (3):
  libc6 (>= 2.34)
  python3:any
  mail-transport-agent | postfix (>= 3.0) | exim4

$ ./run.sh -p demo-lib -V 1.0-1 -r file://$PWD/tests/data/Packages
Прямые зависимости demo-lib 1.0-1: нет
```

Примеры ошибок (код возврата `1`):

```
$ ./run.sh -p bash -V 9.9 -r file://$PWD/tests/data/Packages
Ошибка: версия '9.9' пакета 'bash' не найдена; доступные версии: 5.1-6ubuntu1, 5.1-6ubuntu1.1

$ ./run.sh -p nosuchpkg -V 1.0 -r file://$PWD/tests/data/Packages
Ошибка: пакет 'nosuchpkg' не найден в индексе

$ ./run.sh -p bash -V 1.0 -r file:///no/such/Packages
Ошибка: не удалось получить индекс file:///no/such/Packages: <urlopen error [Errno 2] No such file or directory: '/no/such/Packages'>

$ ./run.sh -p bash -r http://example.org/Packages.gz
Ошибка: не задана версия пакета (--package-version)

$ ./run.sh -p bash -V 1.0 -d 0 -r http://example.org/Packages.gz
Ошибка: глубина анализа (--max-depth) должна быть не меньше 1, получено 0

$ ./run.sh -m test -p A -r tests/data/Packages
Ошибка: режим test будет реализован на этапе 3, пока используйте --repo-mode remote
```

Остальные ошибки параметров (неверное имя пакета, схема URL, режим, версия,
глубина) описаны в разделе «Правила проверки параметров».
